# TiDB 6.2.0 Release Notes

Release date: August 23, 2022

TiDB version: 6.2.0-DMR

> **Note:**
>
> The TiDB 6.2.0-DMR documentation has been [archived](https://docs-archive.pingcap.com/tidb/v6.2/). PingCAP encourages you to use [the latest LTS version](https://docs.pingcap.com/tidb/stable) of the TiDB database.

In v6.2.0-DMR, the key new features and improvements are as follows:

* TiDB Dashboard supports [visual execution plans](https://docs.pingcap.com/tidb/v6.2/dashboard-slow-query#visual-execution-plans), allowing more intuitive display of execution plans.
* Add a [Monitoring page](https://docs.pingcap.com/tidb/stable/dashboard/dashboard-monitoring) in TiDB Dashboard to make the performance analysis and tuning more efficient.
* The [Lock View](https://docs.pingcap.com/tidb/stable/information-schema/information-schema-data-lock-waits) of TiDB feature supports showing the waiting information of optimistic transactions, facilitating quick locating of lock conflicts.
* TiFlash supports [a newer version of storage format](https://docs.pingcap.com/tidb/stable/tiflash/tiflash-configuration#configure-the-tiflashtoml-file), enhancing stability and performance.
* The [Fine Grained Shuffle feature](https://docs.pingcap.com/tidb/stable/system-variables#tiflash_fine_grained_shuffle_batch_size-new-in-v620) allows parallel execution of window functions in multiple threads.
* A new concurrent DDL framework: Less DDL statements blocked and higher execution efficiency.
* TiKV supports [automatically tuning the CPU usage](https://docs.pingcap.com/tidb/stable/tikv-configuration-file#background-quota-limiter), thus ensuring stable and efficient database operations.
* [Point-in-time recovery (PITR)](https://docs.pingcap.com/tidb/stable/br/backup-and-restore-overview) is introduced to restore a snapshot of a TiDB cluster to a new cluster from any given time point in the past.
* TiDB Lightning supports [pausing the scheduling on the table level](https://docs.pingcap.com/tidb/stable/tidb-lightning/tidb-lightning-physical-import-mode-usage#scope-of-pausing-scheduling-during-import) in the physical import mode, instead of on the cluster level.
* BR supports [restoring user and privilege data](https://docs.pingcap.com/tidb/stable/br/br-snapshot-guide#restore-tables-in-the-mysql-schema), making backup and restore smoother.
* TiCDC unlocks more data replication scenarios by supporting [filtering specific types of DDL events](https://docs.pingcap.com/tidb/stable/ticdc/ticdc-filter).
* The [`SAVEPOINT` mechanism](https://docs.pingcap.com/tidb/stable/sql-statements/sql-statement-savepoint) is supported, with which you can flexibly control the rollback points within a transaction.
* TiDB supports [adding, dropping, and modifying multiple columns or indexes with only one `ALTER TABLE` statement](https://docs.pingcap.com/tidb/stable/sql-statements/sql-statement-alter-table).
* [Cross-cluster RawKV replication](https://docs.pingcap.com/tidb/stable/tikv-configuration-file#api-version-new-in-v610) is now supported.
