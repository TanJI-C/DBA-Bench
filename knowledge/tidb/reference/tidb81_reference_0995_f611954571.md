# tiup mirror

In TiUP, [mirror](https://docs.pingcap.com/tidb/stable/tiup/tiup-mirror-reference) is an important concept. TiUP currently supports two forms of mirroring:

- Local mirror: the TiUP client and the mirror are on the same machine, and the client accesses the mirror through the file system.
- Remote mirror: the TiUP client and the mirror are not on the same machine, and the client accesses the mirror through network.

The `tiup mirror` command is used to manage mirrors and provides ways to create mirrors, distribute components, and manage keys.
## Syntax

```shell
tiup mirror <command> [flags]
```

`<command>` stands for sub-commands. For the list of supported sub-commands, refer to the [command list](#command-list) below.
## Option

None
## Command list

- [genkey](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-genkey): generates the private key file
- [sign](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-sign): signs a specific file using a private key file
- [init](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-init): initiates an empty mirror
- [set](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-set): sets the current mirror
- [grant](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-grant): grants a new component owner for the current mirror
- [publish](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-publish): publishes new components to the current mirror
- [modify](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-modify): modifies the attributes of the components in the current mirror
- [rotate](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-rotate): updates the root certificate in the current mirror
- [clone](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-clone): clones a new mirror from an existing one
- [merge](https://docs.pingcap.com/tidb/stable/tiup/tiup-command-mirror-merge): merges mirrors
